    FUSE v0.7.0 Release Notes¶

    Release theme¶

    FUSE v0.7.0 adds composite components for hierarchical, reusable model construction.

    Composite components let users select a configured portion of a model, save that selected fragment as a reusable FUSE mini-model, and place new instances of that mini-model like normal palette components. This release is focused on making large and repetitive models easier to build while keeping simulator plugins clean: composites are a FUSE editor abstraction, not SST or gem5 simulator-native objects.

    Architectural boundary¶

    Composite behavior is owned by FUSE core because it is generic editor/model functionality. Simulator plugins should not need to understand a Composite Component entity.

    Before plugin validation or export, FUSE flattens composite instances into ordinary internal components and links:

    FUSE project with composite instances
  -> core composite flattening
  -> simulator-facing model with ordinary SST/gem5 objects
  -> plugin validation/export

    This preserves the existing plugin boundary: SST-specific behavior stays in the SST plugin, gem5-specific behavior stays in the gem5 plugin, and composite editing remains plugin-agnostic.

    Highlights¶

    Create composites from selected model fragments¶

    Users can select multiple components with the Multiselect tool or Ctrl+click and choose:

    Edit -> Create Composite Component from Selection

    or the same action from the selected item context menu.

    The creation workflow stores the selected fragment as a reusable composite definition. It preserves:

    • selected components and subcomponents
    • links whose endpoints are both selected
    • parameters
    • variable port counts
    • icon paths
    • relative layout
    • subcomponent attachments within the selected fragment
    • candidate port mappings for unlinked internal ports, with explicit exposed/hidden state

    FUSE then replaces the selected fragment with one placed composite instance.

    Selection highlighting for composite creation¶

    Multiselect now uses a clearer component highlight and highlights only links whose endpoints are both selected. Links crossing from a selected component to an unselected component remain unhighlighted and are not treated as internal composite links.

    Local composite definition storage¶

    Reusable composite definitions are stored in the core-owned local table:

    core_composite_components

    Stored definitions appear in the component palette under:

    Composite Components

    They can be dragged into the model view like normal components.

    Explicit composite port exposure¶

    Composite ports are now explicit rather than automatically exposed. When a composite is created, FUSE records candidate boundary ports but exposes none by default. Users choose the public interface of a template or instance by exposing only the internal ports that should be linkable from the parent model.

    Composite edit tabs support two workflows:

    Expose Ports toolbar mode
Right-click port -> Expose Port on Composite / Hide Port from Composite

    Exposed internal ports are highlighted in the edit tab. Hidden ports remain internal and do not appear on the composite boundary. Links to composite ports flatten to the mapped internal component port; links to hidden or missing composite port mappings fail clearly before simulator export.

    Composite instance properties and naming¶

    Placed composite instances have instance-local names and icon paths. New instances receive generated names based on the template name:

    CacheCluster_1
CacheCluster_2

    The Properties panel identifies selected composite nodes as Composite Component Instance objects and shows template metadata such as template name and template ID.

    Tabbed composite instance editing¶

    Double-clicking a composite instance opens a model-view tab for that placed instance's internal mini-model. The project tab remains the leftmost, non-closable tab.

    Nested composites open hierarchy-aware tabs:

    ProjectName
CompositeA_1
CompositeA_1:CompositeB_2

    Edits in a composite instance tab apply only to that placed instance, not to the global composite template stored in the database. Instance edits include exposed/hidden port state. There is still only one global Properties panel and one global Model Outline panel; both follow the active model-view tab.

    Nested composite support¶

    Composite definitions and composite instances can contain other composite instances. FUSE normalizes internal IDs, opens nested edit tabs, and recursively flattens nested composites for validation/export. Composite cycles are rejected during expansion.

    Composite flattening for simulator export¶

    Composite instances are expanded before SST or gem5 validation/export. External links connected to composite ports are remapped to the internal component ports represented by those composite ports. Multiple instances of the same composite receive unique internal names during expansion so simulator exporters do not see duplicate component names.

    Global template editing¶

    Global composite templates can be edited from Edit -> Manage Composite Components... or by right-clicking a composite entry in the component palette and choosing Edit Component.... Template edit tabs include a Save Template Changes button, dirty-state tab markers, and a close prompt when unsaved changes exist.

    When saving a template while the current project contains instances of that template, FUSE asks whether to apply the updated template to existing instances in the open project. Users can save the global template without overwriting current instance-local edits.

    Import/export of composite definitions¶

    Composite definitions can be shared using .fcc files. Users can import shared definitions or export existing local definitions.

    Supported actions include:

    File -> Import -> Import Composite Component...
File -> Export -> Selected Composite Component...
Edit -> Manage Composite Components...

    The composite manager lists locally stored definitions and supports import, export, and deletion without cluttering the normal modeling UI.

    Model Outline integration¶

    The Model Outline now follows the active model-view tab. Selecting a component, subcomponent, or link in the outline selects and highlights the corresponding item in the active model view. This works for the global project tab and for composite edit tabs.

    Known limitations¶

    • Composite icons are path-based. Shared definitions may need icon paths adjusted on another machine.
    • Deleting a composite definition removes it from the local catalog but does not rewrite existing .fse project files or external .fcc files.
    • Composite creation is conservative around boundary links. Only links whose endpoints are both selected become internal composite links.
    • Very deep nested composite paths can make tab labels long.
    • Composite definitions are local until explicitly exported to .fcc and shared.

    Summary¶

    FUSE v0.7.0 introduces hierarchical composite components as a first-class modeling workflow. Users can capture reusable model fragments, place and customize instances, nest composites, share definitions, and still export clean simulator-native SST or gem5 models because composite nodes are flattened before plugin validation/export.
